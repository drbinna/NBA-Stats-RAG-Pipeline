1. During setup, I encountered a port conflict between a local Ollama instance and the Docker service on port 11434. I resolved this by stopping local processes and pulling models into the Docker container, ensuring a reproducible environment as specified in the README.

For data ingestion, I replaced the original pandas to_sql() method with PostgreSQL's native COPY command via cursor.copy_expert(). This streams CSV data directly to PostgreSQL's bulk loader, bypassing SQL parsing overhead. For player_box_scores (36,222 rows), this significantly reduced ingestion time, enabling faster iteration during development.

To select the optimal vector index, I queried PostgreSQL for the total vector count, which was 37,904 vectors (1,682 games + 36,222 player box scores). With ~38K vectors, HNSW was optimal—it provides approximate nearest neighbour search without training, handles updates without rebuilds, and balances speed with accuracy. IVFFlat requires index rebuilds on updates, and StreamingDiskANN needs the pgvectorscale extension rather than the specified pgvector.

I validated my embedding approach using Jupyter notebooks before running the full pipeline. Testing revealed three critical issues: raw team IDs instead of names prevented semantic matching, single date formats failed to accommodate varied query formats like "1-26-24" or "Christmas Day", and player statistics were not embedded at all.

I solved this by joining lookup tables for human-readable names, generating multiple date representations with special game tags (e.g., Christmas Day, New Year's Eve), and extending embeddings to cover both game_details and player_box_scores.

After initial testing showed 67% Top-1 accuracy, I implemented targeted fixes: pre-computing top scorers with "Leading scorer" tags, adding season text such as "2023-24 NBA Season", inferring NBA debuts by matching draft year to the season start, and calculating triple-doubles dynamically. Final results: 78% Top-1 accuracy (7/9) and 100% Top-5 accuracy (9/9). Q7 returned null after verifying the requested date (January 2023) falls outside the dataset range.
